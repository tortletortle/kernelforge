# V0.5 — robust switching and counterfactual audit

Reproduce: Node.js 18+, `node test-v5.mjs`; add `--full` to export the group-level data.

## Design
Keep V3 kernel and frozen V4 baseline. Start MLFQ, compare three policies every 48 ticks. Four deterministic stress scenarios scale estimated residual CPU service by 0.6/1/1.6 or introduce estimated arrivals and wakeups. Require average relative predicted gain > 8%, minimum scenario gain >= 0, and a 48 tick dwell. Reject FCFS if any observed job has not yet received CPU. At a safe boundary, return to MLFQ when an unserved observed job waits >=48 ticks under a non-MLFQ policy. These are illustrative parameter choices, not a proven SLA, probability distribution, confidence interval, hard deadline guarantee, or real-time Linux behavior. Return to the previous default policy is not state rollback. Guard bypasses dwell but cannot interrupt dispatch/migration, does not prevent delays under MLFQ itself, and cannot undo missed latency.

Offline audit forks the exact simulator state at accepted forecast decisions, freezes each alternative policy for up to 48 ticks, and compares integrated active-job and unserved-job counts sampled after ticks. It is a different proxy from the approximate ready-queue projection and is not a full-run oracle. True future appears only in isolated audit branches, not the controller. Overhead of forecasting/auditing is not charged to simulated wall time. Audit excludes emergency fallback decisions.

## Evidence
Seeds 501–508, 8 families (including new shock/heavy), 3 context-switch costs 0/1/3 and migration cost 2. 192 paired groups x 8 policies = 1536 complete runs; 2 targeted fixtures (guard return and counterfactual isolation). Rerun from fetched committed source in JS execution environment, identical reported summary. These are synthetic scenarios; no external trace or Linux test. Group scores normalize equal-weight mean first response and turnaround against RR, floor denominator 1. Regret = score / MLFQ score - 1, per group.

ROBUST response 25.40 ticks, mean per-workload p99 64.24, turnaround 461.60; MLFQ 22.47, 58.84, 546.35. 232 forecast switches (148 positive actual local audit gains, 67 negative, 17 ties), 28 guard returns and 95 veto events (not unique opportunities). Thus a forecast-positive accepted switch can still harm the local audit metric. Wins and average performance are different: ROBUST wins less often than V4, but reduces tail losses. CPU family ROBUST score 0.6885 vs MLFQ 0.8665; shock 0.9199 vs 0.8005. No proof of general superiority or statistical significance. Multiple scenarios are heuristic stress tests; the guard is partial.

## Release decision
Keep MLFQ as default. ROBUST is experimental. Controller observer/history is not included in kernel snapshots. No true livepatch, Linux/QEMU/eBPF, AI code generation or front end implemented. Next priority: instrument real Linux scheduler observations in isolated environment and create external trace format; do not continue exclusively tuning synthetic workloads. Add closed-loop checkpoint and replay plus objective-based latency risk validation before claiming autonomous recovery.
