# V0.2 experiment record

Reproduce with Node.js 18+: `node test-v2.mjs`. V0.1 remains intact. V0.2 is a separate experimental simulator, not a real Linux kernel.

## Observed results
723 scenarios completed without assertion failure in the JavaScript execution environment: 3 exact/replay fixtures plus 144 paired workload groups, each with 4 policies and a deterministic switching/snapshot replay scenario. Four workload families (CPU, IO, mixed, burst), 12 seeds each, 30 jobs per workload and 3 context-switch costs (0,1,3 ticks). ADAPT beat all three static policies on the specified equal-weight normalized response/turnaround score in 6/144 cases, all in the IO/cost=0 stratum. This is a negative result, not proof of universal inferiority. No held-out dataset or external workload traces.

CPU family, cost=3, means across 12 seeds (response, turnaround, overhead): FCFS (423.30,454.48,87.00); RR (87.13,1376.36,956.50); MLFQ (67.61,1784.12,1448.25); ADAPT (423.30,454.48,87.00).

## Model choices and limitations
- Overhead is a synthetic constant per dispatch to a different last-executing job, not measured hardware latency. Idle resets last-executing identity. Dispatch overhead and policy migration overhead are distinct; no explicit cost for migration itself yet.
- A dispatch can be superseded once its pending overhead reaches zero but before a useful CPU tick; the model charges such dispatch attempts, which can bias comparisons. Add a committed-dispatch reference model and sensitivity check.
- The adaptive rule uses observed blocked fraction and fixed thresholds, with no future burst information. Score weights are illustrative, not user-specified service objectives.
- Snapshot restore is for trusted self-produced snapshots only. Not a security boundary or production transaction/rollback mechanism.
- Assertions and replay tests establish limited model invariants, not formal proof. The switching driver is deterministic seed-dependent, not independently randomized at every tick.
- V0.2 uses one CPU, parallel independent IO delays, no cache or scheduler execution effects beyond the synthetic cost. The results cannot establish real Linux performance.
- Next: isolate causes through ablation, verify dispatch semantics, add migration cost and holdout workloads, compare predictive controller to best static and simple baselines.
