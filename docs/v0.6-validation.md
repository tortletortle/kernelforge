# V0.6 implementation and validation status

## Implemented

- CO-RE BPF source attaches to tp_btf sched_wakeup, sched_wakeup_new, sched_switch, and sched_process_exit.
- A per-PID wake timestamp map correlates wakeup with the next switch-in.
- Ring-buffer reservation failures and wakeup-map update failures are counted separately.
- sched_process_exit removes stale wakeup timestamps. Its BTF prototype includes both task_struct pointer and group_dead boolean.
- libbpf userspace collector emits schema-v1 JSON Lines.
- Python stdlib analyzer reports switch/wakeup counts, per-CPU switch counts, wake-to-run latency percentiles, per-PID p95, ring-buffer drops, and map update failures.
- Offline HTML viewer imports JSONL, reconstructs approximate per-CPU execution slices, shows process statistics, and flags continuity gaps. Missing collector summary means drop counters are unknown, not zero.
- Make targets and GitHub Actions workflow are present for simulator and analyzer/viewer tests. Manual workflow_dispatch is enabled.

## Verification performed in this development session

- Python analyzer: 3 test scenarios passed, including latency percentiles, per-CPU counts, dropped events, map update failures, empty traces, and unmatched wakeup handling.
- Viewer inline JavaScript: syntax check passed.
- Viewer demo reconstruction: 11 switch events, 6 wakeup events, 2 CPUs, 10 reconstructed intervals, 4 process rows, 6 matched latency samples. Invalid JSON is rejected; missing summary is detected.
- Existing simulator suites remain separate and unchanged by the Linux observer code.

## Not verified

- The eBPF object and libbpf collector have not been compiled in this session.
- The current isolated build container has clang and a C compiler but does not expose /sys/kernel/btf/vmlinux and does not have bpftool or libbpf development files. Therefore no verifier load, tp_btf attach, or live trace capture was performed.
- The first GitHub Actions run ended before runner allocation (zero job steps and no logs). This is not evidence that the test commands failed; the workflow can be manually dispatched from the repository Actions page if Actions are enabled.
- No real Linux performance, observer overhead, or scheduling-policy effect has been measured.

## Release boundary

V0.6 is an implementation candidate, not a validated kernel integration. Keep it read-only. Do not enable scheduler changes, kernel modules, livepatch, or AI-generated kernel code until build, verifier, attach, loss accounting, observer-overhead, and independent trace-comparison tests pass on a disposable Linux VM or target WSL kernel.
